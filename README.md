# Проект: Очистка и стандартизация данных E-commerce в SQL

## 🎯 О проекте
Этот проект демонстрирует навыки подготовки "грязных" данных (Data Cleaning & Preparation) к последующему анализу. В реальной работе аналитик тратит до 80% времени на очистку данных, и этот скрипт показывает мой подход к решению типичных проблем.

## 📊 Данные
**Источник:** Kaggle (Messy E-commerce Sales Dataset)
**Проблемы в исходных данных:** 
- Дубликаты записей.
- Несогласованный формат дат (смешаны форматы `YYYY-MM-DD`, `DD/MM/YYYY`, `DD Mon YYYY`).
- Разный регистр и сокращения в способах оплаты (`NetBanking`, `net banking`, `COD`).
- Ошибки в написании стран (`U.K.`, `USA`, `germany`, `DE`).
- Пропущенные значения в поле скидки (`Discount_Percent`).

## 🛠️ Инструменты и методы
*   **SQL**: Использование CTE (общих табличных выражений) и оконных функций (`ROW_NUMBER()`) для дедупликации.
*   **SQL**: Применение `CASE`, `LOWER()`, `UPPER()`, `TRIM()` для стандартизации текстовых полей.
*   **SQL**: Обработка `NULL` и пустых строк.

## 🧹 Основные шаги по очистке
1.  **Удаление дубликатов:** Написан запрос с использованием `ROW_NUMBER() OVER(PARTITION BY Order_ID...)` для поиска и удаления повторных записей.
2.  **Унификация платежных методов:** Приведение к единому справочнику (Net Banking, Debit Card, Credit Card, Cash on Delivery, PayPal).
3.  **Географическая стандартизация:** Замена аббревиатур (CA -> Canada, DE -> Germany) и исправление регистра.
4.  **Заполнение пропусков:** Замена пустых скидок на `0` для корректного расчета среднего чека в будущем.

## 💡 Ценность для бизнеса
Чистые данные — фундамент для точной отчетности. После применения скрипта бизнес сможет корректно посчитать выручку по странам, выявить самый популярный способ оплаты и проанализировать средний размер скидки без искажений.
